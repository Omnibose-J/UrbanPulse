# UrbanPulse — LLM project map

Read this first. It tells an agent where each kind of file lives, who owns it, and which command proves what.
The product is described in Korean in the specs under `docs/specs/`; the rules for changing anything are in `AGENTS.md`.

## What this repo is

A Seoul hotspot timing service: for a place the visitor already chose, it tells them when (later today up to 7
days ahead) the place is open-and-lively but not at its busiest. A Python engine runs as scheduled batch jobs
and writes precomputed rows to Postgres; a Next.js app only reads them. Nothing computes on the request path.

## Environment variables

`SEOUL_API_KEY`, `KASI_API_KEY`, `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RAW_DIR`
(local path or `gs://<bucket>/<prefix>`, write-once), `ENGINE_ENV_FILE` (optional; `ENGINE_SKIP_DOTENV=1` wins),
`ADMIN_TOKEN`. The engine reads them via `engine.settings.require(...)`, which exits 1
naming the first missing one; the web app loads the same `.env` through `next.config.ts`. In the cloud the
host injects the same names.

## Data flow (one line per hop)

Seoul citydata API (30 min) → `collect` → `live_obs`, `commerce_obs`, `city_fcst` (+ raw snapshot to `RAW_DIR`)
→ `forecast` (05:00) → `forecast_hourly`, `recommendations` (incl. per-hour `hours`, `strip_mode`), `forecast_log`
→ web route handlers (`/api/places/[id]/week`, `/recommend`, `/api/home`, `/api/map`) → screens.
`evaluate` (06:00) compares yesterday's `forecast_log` and `recommendations.hours` with `live_obs`/`commerce_obs`
→ `eval_daily`, `reco_eval_daily`, `strip_eval_daily`; the weekly re-judgement reads those and edits
`app/engine/config/feature_flags.yaml` (on / reference / off per purpose × tolerance × place group; `strip`
two_step / windows_only). Observations are kept in full: no archive job (decided 2026-10-06).

## Invariants the tests must keep (build contract §4.8)

1. Forecasts use only data known at issue time. 2. A1 windows contain only lively hours. 3. Level thresholds
are monotone. 4. Raw snapshots and `forecast_log` are never modified. 5. `stale` after 90 min without data.
6. A2/B never carry commerce text. 7. Feature flags decide on/reference/off; unlisted = off. 8–11. `hours`
has 15 cells on on/reference rows, is null on off rows; `in_window` cells are `rating = 1` and equal `windows`;
`rating = 0` ⇔ `reason ≠ fit`; `strip_mode` mirrors the flag file.

## Where the numbers come from

Every figure in the specs traces to `analysis/scripts/*.py` and `analysis/data/*.csv` (backtests E1–E5, E14,
re-judgement `rejudge.py`). Bars were pre-registered before each run; the implementer never tunes them.
